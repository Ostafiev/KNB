# KNB backend

Сервер игры: REST API, синхронизация боёв, экономика медяков, админ-панель.

Node.js + Fastify + PostgreSQL + Redis. Один процесс отдаёт и API, и WebSocket,
и админку — три отдельных сервиса означали бы три деплоя и три способа сломаться.

## Запуск

### Через Docker (рекомендуется)

Из корня репозитория:

```bash
cp backend/.env.example backend/.env
docker compose up -d
docker compose exec backend node dist/db/migrate.js
curl http://localhost:3000/health
```

### Без Docker

Нужны запущенные PostgreSQL и Redis.

```bash
cd backend
npm install
cp .env.example .env      # поправить DATABASE_URL и REDIS_URL
npm run migrate
npm run dev
```

Команды:

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер с перезапуском при правках |
| `npm run migrate` | применить непринятые миграции |
| `npm run typecheck` | проверка типов |
| `npm run build` | сборка в `dist/` |
| `npm start` | запуск собранной версии |

## Проверка живости

| Адрес | Что отвечает |
|---|---|
| `GET /health` | 200, только если и база, и Redis отзываются; иначе 503 |
| `GET /health/ready` | применены ли миграции |

## Структура

```
src/
  server.ts              сборка Fastify, корректная остановка
  config.ts              переменные окружения с проверкой на старте
  db/
    client.ts            пул соединений, withTransaction
    migrate.ts           прогонщик миграций
    migrations/*.sql     схема, применяется по порядку имён
  lib/redis.ts           клиент Redis
  routes/health.ts       проверка живости
```

## Схема базы

| Таблица | Зачем |
|---|---|
| `users` | игроки: профиль, рейтинг, баланс, согласие, бан |
| `matches` | матчи: режим, ставка, раунды, счёт, итог |
| `rounds` | раунды: ходы и **серверные** отметки времени для античита |
| `transactions` | журнал движения медяков — единственный источник истины по балансу |
| `referrals` | приглашения и статус выплаты бонуса |
| `withdrawals` | заявки на вывод в TON с ручным подтверждением |
| `reports`, `feedback` | жалобы на игроков и обратная связь |
| `admins`, `admin_audit` | доступ в админку и журнал действий |
| `app_config` | параметры экономики, редактируются без пересборки |
| `events`, `daily_active_users` | поведение игроков для дашборда |

### Три решения, которые важно не потерять

**Баланс меняется только через `transactions`.** Каждая операция пишет строку
в журнал и обновляет `users.coins_balance` в одной транзакции БД. Поле баланса —
денормализованный кэш; источник истины — сумма журнала. Без этого при первом
споре «куда делись медяки» разбираться будет нечем.

**Тайминг ходов ставит сервер.** В `rounds` хранятся `started_at`,
`player1_move_at`, `player2_move_at` — все проставлены сервером. Клиентские
времена не принимаются вовсе, иначе античит обходится подменой одного числа.

**Параметры экономики живут в базе, а не в переменных окружения.** Иначе
«редактирование без пересборки приложения» из ЧАСТИ 6 превращалось бы в редеплой.

### Правила, зашитые в саму базу

Часть требований ТЗ проверяется ограничениями PostgreSQL, а не только кодом —
так их нельзя обойти по забывчивости:

- баланс не может стать отрицательным;
- число раундов только нечётное;
- бесплатный матч (ставка 0) возможен только в режиме «с другом»;
- текстовое условие пари невозможно в случайном подборе;
- нельзя играть, приглашать или жаловаться на самого себя;
- ежедневный бонус — не чаще одного раза в сутки на игрока;
- повторное начисление с тем же `external_id` отклоняется (защита от дублей
  при повторном уведомлении от платёжной или рекламной сети).
