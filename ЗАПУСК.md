# Как запустить игру у себя и открыть её в Telegram

Docker больше не нужен — он требует macOS 14, а на macOS 13 не ставится.
Всё работает напрямую.

> Что означает каждый шаг и зачем нужна каждая программа —
> в файле [ЧТО-ПРОИСХОДИТ.md](ЧТО-ПРОИСХОДИТ.md). Простым языком,
> без технических терминов.

---

## Самый короткий путь

В папке проекта есть файл **`Запуск.command`**. Двойной клик по нему —
и он сам сделает всё: поставит недостающие программы, поднимет базу,
соберёт приложение, запустит сервер и выдаст адрес для Telegram.

Первый раз это минут десять (скачиваются программы), дальше — секунд тридцать.

По ходу он спросит **токен бота** из @BotFather — вставь и нажми Enter.
Спросит один раз, дальше запомнит.

В конце в окне появится зелёный адрес вида
`https://что-то.trycloudflare.com` — его нужно вставить в BotFather:

1. В Telegram открой **@BotFather**
2. `/mybots` → выбери своего бота
3. **Bot Settings** → **Menu Button** → **Configure menu button**
4. Вставь адрес
5. Напиши текст кнопки, например `Играть`

Открой бота, нажми кнопку — игра запустится внутри Telegram.

**Окно Терминала не закрывай.** Пока оно открыто — игра работает.
Закрыл — перестала. Остановить: `Ctrl+C`.

> Если macOS скажет «не удалось проверить разработчика» — нажми правой
> кнопкой по `Запуск.command` → **Открыть** → **Открыть**. Один раз.

Каждый следующий запуск — тот же двойной клик. Адрес будет новый,
его снова надо вставить в BotFather (пункты 1–4 выше). Так работают
бесплатные туннели; на настоящем сервере адрес будет постоянным.

---

## Если хочется руками

То же самое по шагам. Один раз:

```bash
brew install node postgresql@16 redis cloudflared
brew services start postgresql@16
brew services start redis
createdb knb
```

Настройки — скопировать `backend/.env.example` в `backend/.env` и вписать
токен бота и два секрета (`openssl rand -base64 32` даст случайную строку):

```
TELEGRAM_BOT_TOKEN=токен от BotFather
ADMIN_SESSION_SECRET=случайная строка
AUTH_TOKEN_SECRET=другая случайная строка
DATABASE_URL=postgres://localhost:5432/knb
```

Сборка и запуск — из папки проекта:

```bash
cd frontend && npm install && npm run build && cd ..
cd backend && npm install && npm run migrate && npm run dev
```

Проверка в другом окне Терминала:

```bash
curl http://localhost:3000/health
# {"ok":true,"checks":{"postgres":{"ok":true},"redis":{"ok":true}}}
```

Адрес в интернете — в третьем окне:

```bash
cloudflared tunnel --url http://localhost:3000
```

## Как проверить, что сервер действительно работает

Признаки, что данные идут с сервера, а не выдуманы приложением:

- В профиле твоё настоящее имя из Telegram, а не «Никита Волков»
- Баланс ровно **100 медяков** — это регистрационный бонус
- Рейтинг **1000** — стартовый
- Нажми «Забрать» у ежедневного бонуса: станет 120. Закрой приложение,
  открой снова — останется 120
- Открой ту же ссылку на другом устройстве: тот же профиль и тот же баланс

Последний пункт — самая честная проверка. Раньше данные жили в памяти
браузера и на другом устройстве были бы другими.

> В обычном браузере (не в Telegram) приложение открывается в демо-режиме,
> с выдуманным профилем — это нормально, там нет подписи от Telegram.
> Настоящая проверка только внутри бота.

## Что пока не настоящее

Соперники, список друзей и «Последние игры» по-прежнему выдуманы —
настоящие матчи появятся на этапе 4. Сейчас с сервера приходят:
профиль, баланс, рейтинг, бонусы, приглашения и параметры экономики.

## Если что-то пошло не так

Скрипт при ошибке пишет, в каком файле подробности. Пришли мне вывод
нужного — там будет причина:

| Что сломалось | Файл с подробностями |
|---|---|
| установка программ | `/tmp/knb-brew.log` |
| сборка приложения | `/tmp/knb-npm-front.log` |
| сервер | `/tmp/knb-server.log` |
| адрес в интернете | `/tmp/knb-tunnel.log` |

Открыть любой из них: `open -e /tmp/knb-server.log`

**Telegram пишет, что приложение недоступно** — скорее всего закрылось окно
Терминала, или адрес в BotFather устарел. Запусти заново и вставь новый адрес.

**База не поднялась** — выполни `brew services restart postgresql@16`
и запусти заново.

## Вариант с Docker (macOS 14 и новее)

Если система обновится, можно вернуться к контейнерам — файлы на месте:

```bash
docker compose up -d --build
```
